# Your approved inputs

Start with the project brief in `notes/project-brief.md`. Copy only the required input formats from `examples/fictional-workflow/inputs/` into `inputs/private/`, then replace every fictional value with approved records. `inputs/private/` and `reports/` are ignored by git; this is a convenience, not a confidentiality control. Check staged files before every commit.

Keep the frozen fictional example unchanged. Never combine its invented profiles, claims or engine answers with a real live-page report. A live run observes only the supplied public page and technical resources. Identity, claim support and actual AI-answer collection need separate approved inputs and human review.

Each input needs an owner, source, collection date, language, market and permission to use it. Keep exact original text alongside any approved alias or translation. Public repository clones are public unless you deliberately choose a private destination when using the template.
